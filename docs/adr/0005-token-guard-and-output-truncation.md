# 0005. Token 上下文保护与超长输出安全截断

- **状态**: accepted
- **日期**: 2026-10-06

## 背景与上下文

在 Kubernetes 排障场景中，容器错误日志可能包含数万行输出，或集群存在数千个 Pod 资源。直接将全部原始响应注入 MCP 工具输出将迅速耗尽 AI 模型的上下文窗口（Context Window），导致单次调用成本飙升或请求报错。

## 架构决策

在服务端内置 Token 守卫（Token Guard）：
1. **日志输出限制**：`k8s_get_pod_logs` 默认仅返回最近 `100` 行日志；允许客户端指定 `--tail` 参数，但强制上限为 `1000` 行；
2. **列表条目限制**：`k8s_list_resources` 单次最多返回 `100` 个对象；
3. **显式截断提示**：凡是触发截断的输出，均在返回末尾显式附加 `[OUTPUT TRUNCATED: ...]` 警示信息，引导 AI Agent 通过精确过滤或指定命名空间重新缩小查询范围。

## 架构后果

- **正面收益**：有效防御超大输出瘫痪会话上下文，保障会话稳定性与响应经济性。
- **潜在代价**：需要全量排查极长日志时，Agent 必须通过多次定向请求或精确时间范围过滤获取。
