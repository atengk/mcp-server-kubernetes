# 0013. 长耗时操作的 MCP 进度通知 (Progress Notifications)

- **状态**: accepted
- **日期**: 2026-10-06

## 背景与上下文

Kubernetes 某些复合诊断和运维操作耗时较长（例如：跨全集群拓扑树关联分析、观察应用滚动发布状态等）。若服务端仅在最终完成时一次性返回，极易导致客户端触发超时（Timeout），且用户无法感知当前处理阶段。

## 架构决策

基于 MCP 协议原生的 `notifications/progress` 机制：
1. 当客户端在请求中携带 `progressToken` 时，服务端在执行复合耗时任务的多阶段流转中，主动向客户端通道推送分阶段进度事件；
2. 进度事件包含完成百分比及清晰的阶段描述（如：`30% - 正在检索 ReplicaSet 关联...`、`70% - 正在分析 Pod 运行指标...`）；
3. 保持与客户端的长连接心跳活跃，规避超时断连。

## 架构后果

- **正面收益**：解决长耗时操作易超时痛点，用户端交互呈现平滑的可视化进度。
- **潜在代价**：耗时工具实现需要将内部阶段拆解并接入 Context 进度调度器。
