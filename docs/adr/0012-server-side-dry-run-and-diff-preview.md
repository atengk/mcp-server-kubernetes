# 0012. 变更演练 (Dry-Run) 与差异对比预检 (Diff Preview)

- **状态**: accepted
- **日期**: 2026-10-06

## 背景与上下文

在赋予 AI 变更能力（`--allow-write`）时，直接调用 `apply` 或 `delete` 缺乏安全缓冲垫。生产事故往往源于微小字段配置错误（如无意的副本数归零、错误的镜像标签）。

## 架构决策

提供变更预检工具 `k8s_diff_resource` 与 `k8s_dry_run_apply`：
1. **服务端干跑机制 (Server-Side Dry-Run)**：利用 Kubernetes API Server 的 `dryRun=All` 策略，执行完整的准入校验、Schema 检查与 Webhook 拦截，而不实际持久化至 etcd；
2. **结构化差异对比 (Unified Diff)**：对比现有集群状态与干跑演练状态，生成清晰易读的增量变化文本输出；
3. **人类复核闭环**：引导 AI 在执行实质写操作前，优先发起预检对比并向用户呈现 Diff，获得确认后方可落地生效。

## 架构后果

- **正面收益**：形成“预检 -> 对比 -> 确认 -> 生效”的工业级准入闭环，极大降低自动化变更破坏性事故。
- **潜在代价**：变更操作增加了一次额外的 API 预检往返。
