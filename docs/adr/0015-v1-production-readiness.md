# 0015. 1.0.0 正式稳定版生产可用性基线

- **状态**: accepted
- **日期**: 2026-10-07

## 背景与上下文

项目经历 10 个功能子工单研发与 v0.1.0 验证后，各项核心能力（协议传输、动态路由、智能修剪、敏感脱敏、安全门禁、CRD 反射、跨平台包装与 CI/CD 流水线）已全部闭环。在跃迁至 1.0.0 正式稳定版本（General Availability / Production-Ready）之际，需要明确固化 1.0.0 的生产就绪质量契约与版本演进边界。

## 架构决策

1. **版本演进与 Tag SSOT 承诺**：
   - 严格遵循 Tag SSOT 原则，源码内零静态版本号硬编码，版本号的单一事实信源为 Git Tag；
   - 遵循语义化版本（SemVer 2.0），1.0.0 标志着公共 API 与命令行参数进入长期向后兼容（Backward Compatibility）承诺期。
2. **核心安全契约不可突变性**：
   - **默认只读底线**：未经 `--allow-write` 授权严禁注册写操作工具；
   - **数据脱敏底线**：Secret 资源永远保留 Key 并将 Value 掩码为 `[REDACTED]`；
   - **探针受控底线**：`k8s_exec_command` 必须受独立开关 `--allow-exec` 与 15 秒超时熔断硬约束。
3. **企业级生产部署基线**：
   - 正式提供原生的云原生部署清单（`deploy/kubernetes-sse.yaml`），支持企业在 Kubernetes 集群内部以常驻 SSE 模式运行；
   - 提供最小权限 RBAC 声明，防范过度赋权风险。
4. **特性边界收敛**：
   - 1.0.0 聚焦于高频、低延迟、确定性的运维排障交互；
   - 长耗时进阶特性（如基于 MCP `notifications/progress` 的长耗时流式进度通告、Prometheus 运行指标暴露）作为 1.1.0 演进规划，不在 1.0.0 引入不确定性。

## 架构后果

- **正面收益**：向企业用户与社区提供高度稳定、生产就绪的 1.0.0 发行版；API 契约稳定；安全防线坚固。
- **潜在代价**：需对 1.0.0 暴露的所有 CLI 参数与 MCP 工具签名保持向后兼容承诺。
